# Changelog

All notable changes to `@darkmoon_ai/client` are documented here.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.1.0] - 2026-09-24

Initial public release. Implements the frozen cross-version contract
(`CONTRACT_VERSION = 1.0.0`) that the five official Darkmoon integrations
(GitHub Actions, GitLab CI/CD, Jenkins, VS Code, JetBrains) build against.

### Added
- `DarkmoonClient` facade with `mode: auto | oss | pro` capability detection,
  backed by `OssLocalBackend` (on-disk JSON + `darkmoon.sh`) and
  `ProHttpBackend` (`/api/v1` REST + JWT + SSE).
- Pro capability discovery via `GET /system/info` with a root-probe fallback.
- Canonical, normalized enums — severity (`critical/high/medium/low/info`),
  finding status (`exploited/confirmed/unconfirmed/remediated`), campaign status
  (`queued/running/completed/stopped/failed/unknown`); unknown severities
  normalize to `info` (never silently escalated).
- Redaction-safe defaults: `getReport()` returns a redacted body, findings
  expose `evidence: null` unless `includeEvidence` is set; un-redacted values
  require the deliberate two-key opt-in `{ full: true, private: true }`.
- `computeFailPolicy()` / `parseFailOn()` — CI pass/fail derived from findings,
  never from a process exit code.
- `scrubSecrets()` / `scrubDeep()` / `redactReport()` secret-hygiene helpers.
- Runtime schema validation and Pro API major version negotiation
  (`negotiateProVersion`, `SUPPORTED_API_MAJORS`).
- Portable `darkmoon-ci` CLI (`detect | launch | status | summary | findings |
  report | wait | run`) with exit codes `0` pass, `2` fail-policy, `1` error.
- Language-neutral conformance goldens (`fixtures/conformance/*.golden.json`,
  generated by `scripts/gen-golden.mjs`) reused by the JetBrains Kotlin port.
- Dual ESM/CJS build with TypeScript declarations.

### Security
- Real captured lab fixtures are kept in the repository's dev-time `fixtures/`
  test tree only and are **excluded from the published npm package** (`files`
  allowlist ships `dist` + docs only). No evidence bodies, credentials, tokens,
  or target infrastructure ship in the tarball.
